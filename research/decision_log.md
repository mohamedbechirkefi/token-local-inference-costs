- **Consequences:** No measured inference quantity exists after M2. Item (5) is an analysis detail the frozen protocol should state explicitly (see DL-007, A4).

## DL-007 (proposed): Amendments to the draft protocol from the M2 smoke attempt

- **Date:** 2026-11-24
- **Status:** proposed, awaiting the owner. Nothing in `research/protocol.md` was changed.
- **A1, smoke before freeze.** The section 10 smoke matrix could not run: the Ollama server was not running (JRN-0002) and the ARC validation split was not downloaded. Runtime per request, the full-matrix projection against the 4-hour cap, and the timing spread between seeds therefore remain unmeasured. Proposal: before freezing, the owner runs `uv run token-lab smoke --config experiments/smoke-ollama.json` in an exclusive window on AC power (and, if the download is approved, on 10 ARC validation items), then decides n = 300 versus 1,172 and the repetition count from measured values.
- **A2, memory metric.** On Apple silicon, Metal allocations of the runner may not be fully counted in process RSS (unverified concern). The runner now also records the runtime's reported `size` and `size_vram` from `/api/ps` per block and system-wide used memory. Proposal: the protocol names which of these is the reported memory metric, with RSS kept as secondary.
- **A3, sampler overhead.** A 10 Hz sampler that scans every process costs about 8 % of one core on this machine (measured 7.8 ms per scan, noisy). Fixed by PID caching (0.003 ms per cached sample without matching processes). Proposal: keep 10 Hz and record the sampler design in the protocol.
- **A4, repetitions and seeds.** Under temperature 0 the five repetitions are expected to give identical answers, so they inform timing and determinism, not accuracy. Proposal: state in section 4 that accuracy uses the per-item mean over repetitions, that McNemar uses majority correctness (DL-006 item 5), and that the determinism rate is reported per arm; and confirm five repetitions only once real per-item latency variance is measured.
- **A5, chat templates.** `/api/generate` applies each model's own chat template and any default system prompt from its Modelfile, so "no system prompt beyond the template" is not fully under the harness's control. Proposal: record each arm's template and system prompt hash (`/api/show`) in the run manifest before the freeze (not implemented in M2).

- **Date:** 2026-11-26
- **Decided by:** the owner, follow-up answers of 2026-11-26 (`labs/_shared/owner-approvals-2026-11-26.md`, "Follow-up answers, 2026-11-26 (after the TOKEN rerun)"): "**TOKEN EXP-001 status:** "Repeat blocks 3 and 11". Executed under `labs/_shared/TOKEN-repeat-brief.md`.
- **Decision (implementation, closes DL-011 gap 2 for the matrix design).** `src/token_lab/runner.py` now enforces, for every matrix run, the frozen text of `research/protocol.md` section 9, quoted verbatim next to the code and in every new run manifest (`block_rules.quoted`). Operational reading, chosen without changing any frozen value: a foreign model is a model listed by `/api/ps` before or after the block that is not one of the config's arm models; battery is the power source read before or after the block; swap growth for the exclusion is the block's swap delta (end minus start, the section 5 metric) above 512 MiB; a runtime version change is `/api/version` after the block differing from the version at run start; the memory-exhaustion abort fires when swap used minus swap used at block start exceeds 2,048 MiB (checked before every request, by the 10 Hz sampler and at block end), when the runtime becomes unreachable during the run, or when a request error names a terminated or killed runner; the 4-hour cap is checked before every block and every request. An excluded block is repeated once, immediately, with the same seed, item order and warm-up; a repeat that meets a criterion again is recorded and not repeated again (the block is then missing and the run incomplete). Excluded, aborted and cap-interrupted blocks keep their records in `excluded_records` and `excluded_blocks` (never dropped); `records` and `blocks` hold the analysis set. On an abort the result file is still written, the status is "failure" and the CLI exits with code 4.
- **Block-repeat mode.** `token-lab repeat-blocks --config <frozen config> --source <run folder> --blocks 3,11` re-executes the named blocks (1-based, execution order) of an existing run into the next run id with their original runtime seed, item order and warm-up, and records in `manifest.repeat_of` the source run, its SHA-256 and the replaced blocks with the criteria they met. It refuses before any request if the config hash differs from the source run's, if a named block does not exist or meets no frozen exclusion criterion in its own records (no repeat by choice), or if the source run already enforced the rules. The rules apply to the repeated blocks without a further repeat ("repeated once" is then spent). The wall-clock cap counts the source run's duration. `token-lab combine` writes the analysis input in which the repeated blocks replace the excluded ones, which `token-lab report` accepts. The source run is never modified.
- **Schema.** Optional block fields and the `excluded_records` and `excluded_blocks` lists were added to the result schema; version 1.0.0 is kept because the change is additive and every committed result still validates. Reports of runs made before the rules regenerate byte for byte (checked for RUN-EXP-001-0001, RUN-EXP-002-0001 and RUN-EXP-003-0001).
- **Not changed.** Configs, protocols, seeds, item order, template, decoding parameters, the analysis code (`analysis.py`, `stats.py`) and the EXP-002 cold/warm mode. Block 11 of RUN-EXP-001-0001 also met the stopping criterion; under the frozen text the run should have aborted there. The owner's instruction is to repeat it; this entry records that the repeat follows the owner's decision, not a reading of the frozen text by the session.
- **Tests.** `tests/test_block_rules.py` (22 tests, simulated backend, injected machine readings); every other test sees neutral readings (AC power, constant swap) through an autouse fixture, so that a test run on battery does not trip the rules.
- **Consequences:** this is the pre-data commit for the block repeat. EXP-001 status is decided by the frozen rules after the repeat (DL-018).
